NOTES

ISA is 64-bit:
-We use a 64-bit instruction layout.
-Field names are consistent: opcode, rd, rs1, rs2, imm, imm12.
-First forms to support: VM, VV, VS, VI, SA (no VU, since it’s not in the ISA).

PPCI vs LLVM (initial decision):
-PPCI: lighter, easier to modify, faster to prototype encodings and assembly printing.
-LLVM: more setup (TableGen, passes) but stronger optimizations and tools.
-Week 3 decision: use PPCI now to reach “compile to assembly” sooner; keep LLVM as a future option when the ISA settles.

“Theta” handling:
-Parser accepts “theta” now using a non-semantic node.
-We will define a lowering step later (e.g., expand into a short sequence).
-Week 3 goal is “parse + print,” not final semantics.

Data types in the parser:
-Default integers are 64-bit (avoid silent 32-bit).
-Vector element types vs vector width are separated.
-Parser enforces consistent vector width inside each instruction.
